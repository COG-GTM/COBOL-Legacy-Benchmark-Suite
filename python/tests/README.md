# HISTLD00 Python Migration — Test Suite

## Running the tests

```bash
cd /home/ubuntu/repos/COBOL-Legacy-Benchmark-Suite
pip install -r python/requirements.txt
pytest python/tests
```

Run a single file:

```bash
pytest python/tests/test_history_loader.py -v
```

Run with coverage:

```bash
pytest --cov=python python/tests
```

## Fixtures

`tests/fixtures/` contains JSON inputs that mirror the COBOL TRANHIST
records. `tests/fixtures/expected/` contains the corresponding POSHIST
baselines.

| Fixture | Rows | Purpose |
|---|---|---|
| `test_tranhist_small.json` | 10 | All transaction types (PT/PS/TR) and edge values |
| `test_tranhist_medium.json` | 1,000 | Commit threshold testing (250 → 4 mid + 1 final) |
| `test_tranhist_edge.json` | 4 | Zeros, negatives, max-precision, max-length values |

The expected baselines are generated by running `TransactionHistoryRecord`
through the **same** field mapping the loader uses (including
`Decimal.quantize` to the COBOL PIC precision). Audit columns
(`process_date`, `process_time`, `audit_timestamp`) are stamped as empty
strings and ignored by the diff helper because they vary by run.

## Validation methodology

The COBOL HISTLD00 program is not executable in this environment (no z/OS
or DB2 available), so parity is established by:

1. Translating the COBOL PIC clauses, COMP-3 precision, and field-length
   constraints into the Python dataclasses (`HistoryRecord`,
   `TransactionHistoryRecord`, `PosHistRecord`).
2. Implementing the COBOL paragraph structure faithfully in
   `HistoryLoader` (paragraph names map directly to method names).
3. Running deterministic fixtures through both the model layer and the
   end-to-end pipeline, asserting that the output rows match a known
   baseline.

When access to the original COBOL runtime becomes available, the same
fixtures can be fed to the COBOL job and the captured DB2 output written
to `tests/fixtures/expected/poshist_*.json` to perform a true bit-for-bit
parity check without modifying the test code.

## Performance benchmarks

The performance tests assert structural properties (no super-linear
slowdown) rather than absolute throughput, so they remain stable across
hardware. The 100k-row benchmark is gated behind
`HISTLD00_BENCHMARK_LARGE=1`:

```bash
HISTLD00_BENCHMARK_LARGE=1 pytest python/tests/test_performance.py -v
```
