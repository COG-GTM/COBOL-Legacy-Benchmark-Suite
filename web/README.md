# Portfolio Management System — Web Front End

A modern **React + TypeScript (Vite)** single-page application that mirrors the
CLBS BMS 3270 inquiry screens, backed by an in-browser **mock JSON API** so the
whole UI is runnable end-to-end **without a mainframe**.

It is a modernization front end for the COBOL/CICS online inquiry transactions in
this repository — it does **not** modify any COBOL, JCL, copybook, BMS, or SQL
source. The mock API layer is designed so it can later be pointed at a real
backend (see [Production deployment](#production-deployment)).

## What it mirrors

| Web route        | BMS map (`src/maps/INQSET.bms`) | COBOL program              | Purpose                                   |
| ---------------- | ------------------------------- | -------------------------- | ----------------------------------------- |
| `/`              | `MENMAP`                        | `INQONLN` (menu)           | Main menu / option selection              |
| `/positions`     | `POSMAP`                        | `INQPORT`                  | Portfolio position inquiry by account     |
| `/transactions`  | `HISMAP`                        | `INQHIST`                  | Paginated transaction history by account  |
| `*` (not found)  | `ERRMAP`                        | error / `NOTFND` handlers  | System-error / not-found screen           |

## Requirements

- **Node.js 18+** (developed and verified on Node 22)
- npm

## Getting started

```bash
cd web
npm install          # installs deps and runs `msw init public/` (postinstall)
npm run dev          # start Vite dev server + in-browser mock API
```

Then open the printed URL (default <http://localhost:5173>).

> The mock API is provided by [MSW](https://mswjs.io) and runs **inside the
> browser** via a service worker (`public/mockServiceWorker.js`). There is no
> separate API server process to start — `npm run dev` is all you need. The
> worker is started in [`src/main.tsx`](src/main.tsx) before the app renders.

### Try it

Seeded accounts (from `documentation/operations/test-data-specs.md`):

| ------------ | -------------------- | ---------------------------------------- |
| `ACCT000001` | GROWTH PORTFOLIO     | 13 transactions → 2 pages of history     |

## API contract

The client ([`src/api/client.ts`](src/api/client.ts)) speaks a small JSON API:

### `GET /api/portfolios/{account}`

Mirrors `INQPORT` (VSAM `POSFILE` read → `POSMAP`). Returns the portfolio
master plus its positions:

```jsonc
{
  "portfolio": {
    "portfolioId": "PORT0001",
    "accountNo": "ACCT000001",
    "clientName": "GROWTH PORTFOLIO",
    "clientType": "I",          // I=Individual, C=Corporate, T=Trust
    "createDate": "20240320",   // PIC 9(8) YYYYMMDD
    "lastMaintDate": "20240320",
    "status": "A",              // A=Active, C=Closed, S=Suspended
    "totalValue": 12345678.99,  // COMP-3 with implied decimals
    "cashBalance": 250000.00
  },
  "positions": [
    {
      "portfolioId": "PORT0001",
      "date": "20240320",
      "investmentId": "IBM0000001", // POS-INVESTMENT-ID → "Fund ID"
      "fundName": "IBM COMMON STOCK",
      "quantity": 5000.0,           // POS-QUANTITY (Units)
      "costBasis": 625000.00,
      "marketValue": 712500.00,
      "currency": "USD",
      "status": "A"
    }
  ]
}
```

`404` → `{ "message": "Position not found for account", "code": "00013" }`.

### `GET /api/portfolios/{account}/transactions?page={n}`

Mirrors `INQHIST` (DB2 `POSHIST` cursor fetch → `HISMAP`). **Page size is fixed
at 10** to mirror the COBOL fetch of 10 rows (`WS-HISTORY-ENTRY OCCURS 10 TIMES`).
The projected columns are exactly those selected by `INQHIST.cbl`:
`TRANS_DATE, TRANS_TYPE, TRANS_UNITS, TRANS_PRICE, TRANS_AMOUNT`.

```jsonc
{
  "account": "ACCT000001",
  "page": 1,
  "pageSize": 10,
  "total": 13,
  "totalPages": 2,
  "transactions": [
    { "transDate": "2024-03-20", "transType": "BU", "transUnits": 500.0,
      "transPrice": 125.00, "transAmount": 62500.00 }
  ]
}
```

## Data typing: COBOL copybooks → TypeScript

The interfaces in [`src/types/portfolio.ts`](src/types/portfolio.ts) are derived
**directly** from the copybook field layouts. Each field is annotated with its
source copybook and PIC clause.

- `Portfolio` ← `src/copybook/common/PORTFLIO.cpy` (`PORT-RECORD`)
- `Position` ← `src/copybook/common/POSREC.cpy` (`POSITION-RECORD`)
- `Transaction` ← DB2 `POSHIST` columns as fetched by `INQHIST.cbl`
  (scale from working-storage `WS-TRANS-*` host variables)

**COMP-3 / implied decimals.** COBOL packed-decimal fields with an implied
decimal point (the `V` in e.g. `PIC S9(13)V99 COMP-3`) carry no physical decimal
character on the mainframe. They are modelled here as plain JavaScript `number`s
with the implied scale already applied (e.g. `12345678.99`). Applying that scale
during marshalling is the responsibility of the API gateway (below). The COBOL
`88`-level condition names (client type, status, transaction type) become string
literal union types with human-readable label maps.

## Production deployment

**The COBOL `INQPORT` / `INQHIST` programs cannot be called directly from a
browser.** They are CICS programs that communicate via a `COMMAREA`
(`INQCOM.cpy`), read VSAM (`POSFILE`) and DB2 (`POSHIST`), and render 3270 BMS
maps — none of which is reachable over HTTP/JSON.

To run this UI against real mainframe data, expose those programs as JSON over
HTTP using one of:

1. **z/OS Connect EE** — define API requesters/providers that map the
   `INQCOM` COMMAREA (and the `POSREC` / `POSHIST` result layouts) to JSON
   request/response schemas, and publish `GET /api/portfolios/{account}` and
   `GET /api/portfolios/{account}/transactions` backed by `INQPORT` / `INQHIST`.
2. **CICS Web Services** — front the programs with a CICS-provided RESTful/SOAP
   service (WSBIND from the COMMAREA copybooks) via the Liberty JVM server.
3. **A reimplemented service** — a Java/C#/Node service that reproduces the
   `INQPORT`/`INQHIST` business logic against a modernized data store.

Whichever gateway is chosen, the API gateway must:

- key inquiries on the account number (`INQCOM-ACCOUNT-NO`, `PIC X(10)`);
- apply COMP-3 implied-decimal scaling when marshalling numerics to JSON;
- keep the transaction page size at 10 (or expose it) to match `INQHIST`;
- map the COBOL `NOTFND` / error paths to HTTP `404` / `5xx` with the
  `{ message, code }` error body this client already understands.

Then point the front end at it and **remove the mock**:

```bash
# .env  (or environment of your choice)
VITE_API_BASE_URL=https://your-zosconnect-gateway.example.com
```

`VITE_API_BASE_URL` is read in [`src/api/client.ts`](src/api/client.ts). When it
is set, requests go to the real gateway instead of being intercepted by MSW. To
fully disable the mock, remove the `enableMocking()` call in
[`src/main.tsx`](src/main.tsx) (or gate it on `import.meta.env.DEV`).
